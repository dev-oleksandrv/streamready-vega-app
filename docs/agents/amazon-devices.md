# Amazon Devices Builder Tools MCP

How to use the `amazon-devices-buildertools-mcp` server (configured in `.mcp.json` for Claude Code; see `AGENTS.md` for other agents). Adapted from the context file generated by `init-context` (document version 5.0.0).

## Session setup

Do this once per session, before the first call to the MCP server. It is not needed for sessions that don't use the server. Don't narrate these steps.

1. **Send project context.** Read `.adbt-config.json` from the repo root and call `set_project_context({"config": <parsed contents>})` once.
2. **Platform.** This project is Vega-only; `.adbt-config.json` sets `platform.default` to `vega_os`. Use `target_platform: {"device_os": ["vega_os"]}` for every `list_documents` and `search_documentation` call.
   - Exception: catalog ingestion work (catalog / EMBER / CDF feeds) is platform-independent. Use `{"device_os": ["vega_os", "fire_os"]}` for it and load `ftv_appstore_sdk_integrations_get_started.md` instead of the Vega guide.
   - Override for a single call only when the user literally says "Fire OS" or "Android". "Fire TV" is the device family, not a platform.
3. **Load the guide.** Call `read_document(document_uri: "react_native_for_vega_get_started.md")` and follow it for the rest of the session.

## Document tools

- `list_documents` and `search_documentation` require `target_platform` (see above). If it is missing they return `PLATFORM_UNKNOWN`.
- `read_document` takes only `document_uri` (a single string).

```
list_documents(target_platform: {"device_os": ["vega_os"]})
search_documentation(query: "IAP setup", target_platform: {"device_os": ["vega_os"]})
read_document(document_uri: "vega_iap_overview.md")
```

## Workflows from the MCP server

When following a workflow the server provides (implement, integrate, configure, test, build, deploy, submit):

- Execute its numbered steps in order. Adjacent non-blocking steps can be batched, but never skip one.
- At a `🛑 YIELD` step, stop and wait for the user. If they say "skip" or "later", mark the step PENDING and continue.
- When a step says to read an external document, extract only what the step needs and return to the workflow.
- When a workflow says "Next Step: proceed to [workflow X]", tell the user and load that workflow.
- Keep a visible list of PENDING steps and remind the user of them at the end of each workflow and before submission.
